## Counting what is a question (12:03, 12:11)

An AMC8 worksheet reported 26 questions for a paper holding 25. The extra row
was the coordinate labels lifted off a diagram; the SHSAT papers carry the same
shape of junk in rows reading `CONTINUE TO THE NEXT PAGE` and `FORM B`.

A row counts when it reads like a sentence or asks for a calculation. Measured
across every stored question that drops 23 rows, all page furniture, none
carrying a printed number. AMC8 goes 26 → 25, both SHSAT papers stay at 114.

Kept as a display rule rather than a delete — the same test applied at ingest
rejected real questions, so the rows stay stored, visible and deletable.

The follow-up eight minutes later: the card read "Questions 25" beside
"Unchecked 26", because only one of the two counts had been filtered. Both now
share one `IS_QUESTION` expression in [app/worksheets/page.tsx](app/worksheets/page.tsx),
so they cannot drift apart again.

## Questions split across a page boundary (13:00)

Extraction reads one page at a time and the model never sees the page before or
after. A question whose stem ends at the foot of page N and whose options begin
at the head of page N+1 is never whole in either request. Five questions on the
AMC8 2024 paper are split this way.

Two deterministic repairs, both running before `repairPrintedNumbers` and
`renumberQuestions` because joining changes the count and the order:

- `joinSplitQuestions` folds two rows into one where the extractor returned both
  halves — a stem with no options at the bottom of a page, a full option list
  under something that asks nothing at the top of the next. That is question 11,
  and only question 11.
- `recoverCarriedChoices` handles the commoner shape, where the extractor
  returned nothing for the second half at all. A bare option block is not a
  question, so the model drops it and the stem keeps no record its answers ever
  existed. Questions 5, 14, 18 and 23. No join can reach them; the options are
  still sitting in the next page's text layer, above the first question printed
  there.

Ordering within a page got its own module. bbox is not exact — question 4 came
back with a top of 1428 and question 5 with 1379, so geometry alone puts them
the wrong way round. Printed numbers decide when the page has them, geometry
when it does not, arrival order last, and each only when it covers the whole
page.

Both rules were swept over every stored row and page before being wired in
(713 rows, 353 pages, 9 worksheets), per the rule that already cost this
codebase two shipped heuristics that read correctly and were wrong on real
data. The join proposed one pair, the correct one. The parser found five
blocks, all on AMC8, all correct, nothing on the 348 SHSAT pages. Zero false
positives.

Result: AMC8 goes from 19 of 25 questions carrying options to 24 of 25.
Question 25's options are not in this PDF's text layer on any page, so there is
nothing to recover and it is left blank rather than guessed at.

**Tried and reverted:** telling the model to return a carried option block as
half a question. It produced no orphan rows at all, and started relabelling
stem-only questions `free_response`, which hides the damage from every
choice-bearing check and from the review screen. `lib/ai/prompts.ts` unchanged.

## LaTeX eaten by JSON.parse (13:31)

The bigger find of the day. A model told to write plain text still reaches for
LaTeX, and the reply lands in one of two states:

- `\sqrt`, `\pi` — not JSON escapes, so the whole response fails to parse and a
  page of questions is lost. Loud, and already survivable.
- `\frac`, `\times` — the dangerous half. These parse without complaint, and
  `\frac{44}{11}` becomes a form feed followed by `rac{44}{11}`. An AMC8
  question shipped reading `?rac{44}{11}` with nothing anywhere reporting a
  problem.

Repaired before the first parse rather than in the catch, because the damaging
case never throws. `repairLatexEscapes` walks the text tracking string
boundaries and doubles the backslash on a run of letters JSON would misread.
Narrow on the six colliding letters — b f n r t u — so a real line break stays a
line break; those are rewritten only when the whole letter run names a command.

Also routed the Anthropic provider's classify path through `parseModelJson`; it
was calling `JSON.parse` directly and skipping the repair every other provider
gets.

Rows already in the database needed a second pass. `normalizeMath` recovers a
command from the control character it decoded to, and `looksUnrendered` spots
one — a command taking no argument leaves no braces, so without this there is
no tell at all. `repairUnrenderedMath` re-normalises a worksheet in place and
rehashes what it rewrites, for the same reason the split join does: a row
holding the hash of text it no longer contains stops matching itself. It runs
last in the audit script, after the stages that move text around.

Two smaller fixes found alongside: `\dfrac` and `\tfrac` now read as fractions
(the pattern matched only the `d`), and leftover control characters are stripped
rather than shown mid-sentence.

Tests cover both failure shapes, the cases that must not be touched (line
breaks, tabs, escaped quotes, an already-escaped backslash, text outside a
string), and end to end through `parseExtraction`. Full suite green at 407.

## Landing page animations play unconditionally (15:34)

The hero sequence, the dashboard tilt, the theme-toggle knob and the route
crossfade each collapsed to a static end state under `prefers-reduced-motion`.
On a machine with animation effects switched off — the default on some managed
Windows installs — the landing page never demonstrated anything, which is most
of what it is for.

Removed knowing the cost: the read-head traverses the sheet, the pills slide,
the mock rotates, and those are exactly the motions the setting exists to
suppress for people with vestibular disorders. Each site carries a note saying
the absence is deliberate, so it is not read as an oversight and quietly
restored, and records the cheaper compromise if it is ever wanted — keep the
sequence, cross-fade in place, drop only what traverses the screen.

The `@supports` gate on the scroll-driven tilt stays. That one is a browser
capability check, not a preference, and without it the animation resolves to 0s
by accident rather than by intent.

## Dealing the hero panel (18:46)

The panel now arrives the way a card is dealt onto a table rather than fading
up: from behind and below, pitched on two axes, swinging flat and overshooting a
few degrees past level before it settles. That needs a perspective on the parent
— without one the rotations collapse into a shear and it reads as a slide. The
rest of the sequence moves back behind it, so the extraction starts once there
is something to extract into.

The forgetting curve draws itself left to right, its area fill waits for the
line that bounds it, and a band of light runs the length of the chart as it
brightens.

**Worth recording so it is not tried again:** drawing the line by
`stroke-dashoffset` does not work here. `pathLength` normalisation is ignored
under `vector-effect: non-scaling-stroke`, so the dash is measured against the
rendered length and tiles across the path instead of spanning it. The stroke
needs `non-scaling-stroke` to avoid rendering roughly nine times too heavy in
the stretched viewBox, so the dash was the part that had to go. A shutter the
colour of the page reveals the same geometry with no arithmetic that can drift
with the viewport.
